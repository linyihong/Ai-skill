### 2026-07-31 - 已簽署的合約，review 產出形狀不同

Status: candidate

#### One-line Summary

合約已簽署時，「修正條文」是廢的產出——改不動；review 的價值改為存續義務、現在還能做什麼、以及下一份合約的改善清單。

#### Human Explanation

Review 流程的預設假設是**產出會被拿去談判**：找出風險 → 給修正方向 → 排退讓順序。
這個假設在合約已簽署時整個崩掉。條款不會因為指出問題而改變，redline 沒有收件人。

但已簽署的合約**更需要**被審閱，只是問的問題不同：

| | 未簽署 | 已簽署 |
| --- | --- | --- |
| 核心問題 | 這樣簽對我方好不好？ | 我現在被什麼綁住？還能做什麼？ |
| 風險清單的用途 | 決定要不要改、怎麼換 | 決定要**防禦**什麼、**準備**什麼證據 |
| 主要產出 | 修正條文 + 退讓順序 | 存續義務盤點 + 可行動事項 + 下份合約改善清單 |
| 時間軸 | 簽署前 | **期間可能已屆滿**，但存續條款仍在跑 |
| 新增維度 | — | 消滅時效、證據保全、既有事實的歸責 |

三個容易被漏掉的點：

1. **存續條款盤點**。多數合約有「本條於契約終了後仍有效」的條款清單。期間屆滿 ≠ 義務結束。
   保密、IP、責任限制、競業常在此列，且**保密若無期間上限即為無期限義務**。
2. **既有事實會改變條款的威脅程度**。同一條懲罰性條款，在「我方確實未履行」與
   「停滯可歸責於對方」兩種事實下，威脅程度天差地遠。所以已簽合約的 review
   **必須把事實狀態當成輸入**，不能只讀條文。
3. **產出的最大價值往往是下一份合約**。本份改不動，但同樣的坑會在下一份重現。
   把「這次的問題 → 下次必爭」做成對照表，比再多的本份風險描述有用。

#### Trigger

Task type 為 `review`（或 `explain`），且合約**已經簽署／已生效**——
使用者語氣通常是「雖然已經簽了」「幫我看看有什麼風險」。

#### Evidence

- Tool: 合約全文審閱 + 官方法規資料庫條文查證（A 層）
- Sanitized excerpt: 一份已簽署且期間已屆滿的委外開發合約，存續條款涵蓋 IP、
  保密、責任限制與讓與禁止；保密義務無期間上限，且被排除於責任上限之外。
  原 review slice 的五階段（結構 → 逐條 → 風險 → 缺漏 → 建議修改與退讓順序）
  跑到第五階段時無收件人，需改為可行動事項與下份合約清單。
- Evidence path: `<PROJECT_ROOT>/<合約資料夾>/風險評估-<日期>.md`（個案留在業務專案）

#### Generalized Lesson

Review sub-flow 需依**簽署狀態**分流：

- **未簽署**（可談判）→ Stage 5 產出「建議修改方向 + 退讓順序 + 若對方拒絕怎麼辦」。
- **已簽署**（不可談判）→ Stage 5 改為三段：
  1. **存續義務盤點**——哪些條款在期間屆滿後仍有效、有無期間上限、是否被排除於責任上限外。
  2. **可行動事項**——依現況事實，現在還來得及做什麼（證據保全、時效確認、
     資產盤點、義務的持續管理）。並標明**每項的風險等級**：純內部整理是零風險，
     對外發函具法律效果，兩者不可混為一談。
  3. **下一份合約的改善清單**——「這次的問題 → 下次必爭」對照表。

另外：已簽署的 review **必須把當前事實狀態當成 intake 的一部分**（付款進度、
交付進度、停滯原因與歸責、有無對方的主張），否則風險評估會建立在錯誤前提上。
事實變更時，評估要同步修訂而非另開一份。

#### Agent Action

接到已簽署合約的 review 時：

- intake 增問：**已履行到哪、款項收到哪一期、有無停滯及其原因、對方有無主張過違約**。
- **不要**輸出修正條文作為主產出（可作為「下份合約改善清單」的素材）。
- 產出「可行動事項」時，**逐項標示風險**；純內部的證據整理與具法律效果的對外動作
  必須分開，且後者建議先諮詢當地律師。
- **不要代擬對外的請求函或催告文書**——屬 Red tier 的對外法律文件。
- 事實更新時**就地修訂**既有評估並標註更新日，不要留下互相矛盾的兩份文件。

#### Goal / Action / Validation

- Goal: 讓已簽署合約的 review 產出可用，而不是產出一份改不動的 redline。
- Action: 依簽署狀態分流 Stage 5；已簽署者輸出存續義務盤點 + 風險分級的可行動事項 +
  下份合約改善清單。
- Validation or reference source: 檢查產出中是否存在「無收件人的修正建議」；
  檢查存續條款是否逐條盤點且標明有無期間上限；檢查可行動事項是否標示風險等級。

#### Applies When

- Task type 為 `review` 或 `explain`，且合約已簽署或已生效。
- 合約期間已屆滿但有存續條款。
- 履約中出現停滯、未付款或其他既成事實，需要據此評估風險。

#### Does Not Apply When

- 合約尚未簽署（走原有的修正建議 + 退讓順序路徑）。
- 已進入形式爭議（收到催告、正式請求或訴訟文書）→ 依 risk-classification 升 Red，
  僅做升級不出實質建議。
- 純 `compare` 任務（比較版本差異，不涉簽署狀態）。

#### Validation

- 產出中「建議修改」段落若存在，是否已歸入「下份合約改善清單」而非當作本份的行動項？
- 存續條款是否逐條列出並標明期間上限與是否受責任上限保護？
- 可行動事項是否每項標示風險（零風險／具法律效果）？
- 當事實狀態更新時，評估是否就地修訂並標註更新日？
