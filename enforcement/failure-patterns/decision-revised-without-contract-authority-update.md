# Decision Revised Without Contract Authority Update（改了決策卻沒改契約權威文件）

Status: candidate
Class: `traceability-gap`

## Trigger

專案同時存在兩種文件：

- **計畫／決策文件**（plan、ADR、decision log）—— 記錄「我們決定怎麼做」
- **契約權威文件**（API 契約、整合文件、schema 說明）—— 記錄「實作必須符合什麼」

而某個既有決策被改版：`D8` 從 A 案改為 B 案、某欄位語意反轉、某驗證規則從「拒絕」改為「忽略」。

## Failure Mode

Agent 把改版寫進計畫文件，視為「決策已更新」，然後結案。契約權威文件仍留著舊語意。

問題不在於文件不同步這件事本身，而在於**兩份文件的讀者不同**：

| 文件 | 誰讀 | 何時讀 |
| --- | --- | --- |
| 計畫／決策 | 本次執行者 | 執行當下 |
| 契約權威 | 未來的實作者、其他模組、其他 slice | 幾週後、跨團隊 |

改版通常發生在計畫文件的上下文裡，所以更新它是自然動作；契約文件不在視野內，於是被漏掉。而後續實作者讀的是契約文件 —— 他會照舊語意實作，且**不會收到任何衝突訊號**，因為契約文件本身自洽。

實例：`D8` 由「site 聯集驗證」改為「Host catalog 驗證＋catalog-scoped replace」，計畫已更新，但整合文件仍只寫讀取語意、未寫入寫入語意。照該文件實作會做出全量覆寫，**靜默刪除**另一個 Host 管理員設定的授予 —— 沒有錯誤、沒有測試會紅，資料就是少了。

## Risk

- 後續實作照舊語意產出與決策相反的行為，且該行為在該 slice 的驗證範圍內完全合法
- 錯誤最可能的形態是「沉默的資料流失」而非例外：新語意常是為了保留某些東西，舊語意則否
- 跨 slice／跨 session 才會顯現，屆時原始決策脈絡已不在任何人的上下文裡

## Required Agent Action

**決策改版是一次多落點寫入，不是單一文件編輯。**

1. **改版時先列落點清單，再動筆。** 至少檢查：計畫／決策文件、契約權威文件、manifest／schema、既有實作的 doc comment。
2. **問「誰會照這份文件做事」而非「這份文件提到它了嗎」。** 契約文件不需要提到決策編號才算相關 —— 它描述同一個行為就算。
3. **讀寫語意成對檢查。** 決策若改動寫入行為，契約文件常只有讀取語意；「沒寫」比「寫錯」更難發現，因為沒有矛盾可偵測。
4. **改版後重讀契約文件，模擬一位只有這份文件的實作者。** 他會做出什麼？若與新決策不同，文件就還沒改完。

## Prevention Gate

宣告某決策改版完成前：

- 這個決策約束的是行為，哪些文件描述同一個行為？我全部檢查過了嗎？
- 若有人只讀契約文件實作，他的產出會符合新決策嗎？
- 新決策是否改動了寫入／刪除語意？契約文件是否只寫了讀取語意？
- 舊語意造成的錯誤會是例外，還是靜默的資料差異？後者要更謹慎。

## 驗證

1. 改版 commit 的 diff 同時觸及決策文件與契約權威文件（或有書面理由說明後者確實不受影響）
2. 契約文件的敘述可獨立支撐正確實作，不需要讀者另外知道決策編號
3. 若決策涉及寫入語意，契約文件明確寫出「哪些列會被刪除、哪些不會」
4. 後續 slice 的驗證中，有針對新語意的直接斷言（而非只斷言請求成功）
