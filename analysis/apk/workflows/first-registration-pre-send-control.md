# 首次裝置建帳的送出前對照

用於已授權的裝置登入分析。當獨立客戶端收到表面成功但缺少會話時，用同一條件區分首次建帳、舊會話恢復與合成識別。

1. 保留既有會話作為恢復對照。另建隔離使用者或全新模擬器，記錄系統識別是否為首次出現。
2. 在 App 組好請求之後、網路送出之前攔截首個建帳請求。確認攔截涵蓋重試並避免 App 先消耗首次狀態。
3. 在記憶體比對獨立實作的 canonical input 與各簽章，再由獨立客戶端用新的時間戳與 nonce 送出一次。原始識別、簽章、token 及請求值不進日誌或 Git。
4. 驗證業務成功、新建證據與會話憑證存在。以同一會話發送已授權的唯讀查詢，確認會員相符。
5. 分別標記「獨立傳輸」和「獨立身分初始化」。若測試使用作業系統或官方 App 產生的輸入，將依賴寫入 SDK 驗收。
6. 若有控制組與變更組，固定傳輸與測試狀態，每次只替換一類欄位。解壓後、模型轉換前的欄位集可用來定位回應差異。
