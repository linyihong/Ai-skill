# Unity 動態流程驗證

先讀 [決策入口](../decision-workflow.md)。本程序用於授權 Unity／IL2CPP 分析中，靜態內容已可讀回，但移動、到站事件或完成流程仍未驗證的情況。這是待 dogfood 的程序補強，並非跨目標已驗證方法。

## 先定義動態 oracle

將輸入／起點、執行中狀態、終點、事件與完成／取消分開記錄。終點正確只支持終點主張；若目標包含動畫或移動過程，需時間序列位置與畫面。路徑可能有跳躍、瞬移、回退或特殊格分支，預期依自然證據與資料契約決定，不預設單調移動或固定格數。

## 靜態證據接入

1. 核對 binary／metadata fingerprint、工具版本及方法身分，保存 RVA、image base 與 Runtime module-relative address 的換算。
2. 依目前未解差異擷取入口、狀態寫入、dispatch 與完成回呼的有限 XREF／指令／反編譯。將間接呼叫與缺失標為 unknown。
3. 從靜態證據提出可區分預測，選入口或出口的被動 hook。靜態呼叫圖不證明 Runtime 已走該分支。
4. 工具接入的驗收與目標功能驗收分開。特定工具不可用時明記 blocked，替代工具結果另列來源。

針對大型 stripped binary 的局部樣本，可用同版 metadata 界定反組譯與 flow reference 的範圍。反編譯器可能跨越取樣邊界；遇到相鄰函式落入、間接跳轉或不明參數時，用指令與獨立 Runtime 證據核對。此作法已在單一目標試用，仍待其他目標驗證。

## 自然對照與最小實驗

- 先確認乾淨場景、有效物件與既有 hook 的觀測契約，稀有窗口前掛齊關鍵點。
- 記輸入事件、來源與目標身分、邏輯位置、畫面位置、移動狀態及完成／取消。保留 session／phase／時間與事件關聯；不能只靠時間接近配對。
- 依假說選普通與邊界／特殊路徑，保存選樣理由；未觀測分支維持 not-tested。
- 比較事件有序關係與資料相依性。跨執行緒或非同步回呼可能交錯，不能僅以全域 log 行序推定因果。
- 先用被動對照裁決，再做可回復的 lab 操作。執行前寫預測、反駁條件、副作用及回復方式。

## 動態回放與獨立驗收

| 檢查 | 驗收來源 |
| --- | --- |
| 起點與輸入契約 | 修改前讀回、已記錄的 fixture 或自然輸入 |
| 實際移動／中途狀態 | 與操作分開的唯讀位置序列及時間序列畫面 |
| 終點與事件 | 邏輯位置、畫面對應與實際 dispatch／結果讀回 |
| 完成 | 回呼、佇列或狀態轉換，核對重複／遺漏；完成次數依該契約 |
| 穩定性 | 延後讀回、重複執行、重進與取消／失效物件測試，按目標選必要項 |

Unity 物件操作依已驗證的主執行緒契約。不要為了讓畫面停穩而停掉本輪正要驗證的移動驅動；確需暫停作區分實驗時，單列為 lab 干預並解除，不能作自然流程 PASS。

對含多段移動的流程，按同一物件與每段起始事件分組，比對位置收尾、到站派發與特殊事件的巢狀關係。中途段的收尾可以與到站段共用方法；完成次數應依該段的預期事件計算，並以目標物件身分與獨立畫面交叉核對。此區分已在單一自然案例試用。

取樣前辨識真正呈現動畫的節點。根物件可能在移動期間留在起點，渲染子物件則隨動畫移動。記錄兩者及目標節點的位置，用畫面交叉核對。若既有回放會在 action 後直接補定位，將補定位移到受測窗口之外，再判斷是否真的執行了移動。

單獨回放一個 chain element 時，明列包含的後續元素與資料上下文。特殊終點的到站可以獨立通過，後續事件仍須以完整鏈或對應的最小資料 fixture 驗證。依巢狀事件判定 callback 的角色，避免把同一 action 的多個回呼合算為重複完成。

驗證條件式到站事件時，讓正例與對照使用相同終點、起始狀態及鏈元素，只改候選觸發資料。以新建的 lab 資料物件提供輸入，先獨立讀回，執行後分別核對到站、事件與 HUD。跨行程重跑時重新解析物件並比對結果。

取消測試要在獨立位置確認已起動且未到站時介入，並在重設返回後繼續觀測。即使狀態旗標已清，延後的閉包仍可能改寫位置。若有可讀的完成回呼容器，分開記錄其 pending 狀態、派發與位置寫入；將等待舊回呼後的恢復結果與真正取消分開裁決。

若實驗需要讓舊委派失效，先辨識單一或 multicast 回呼，逐項驗證目標身分與其所屬 action。重設返回後重新核對容器及委派身分。所有權不明時應停止介入。正反對照使用同一介入時機及延後觀測窗，並記錄重新使用物件的時間邊界。此方法已在未加入共用佇列的單一 lab 移動試用。

立即重用實驗應讓舊動作和新動作走不同目標，並用新動作單獨執行及延後重用作對照。新動作的終點、完成次數、完成時間及中途位移須分開驗收。若基線出現提早收尾，先保留反例，再從可比場景重跑。清除舊委派後仍需觀測事件來源；延後對照可用來區分時序，但其時間不直接作通用就緒門檻。

完整路徑的驗收應列出中途的所有必要節點，並核對每段目標、渲染位移、完成事件和最終佇列狀態。若路徑會回到起點，只驗起訖位置無法區分走完整圈、跳格或完全沒動。用原速畫面獨立核對順序，分開記錄路徑是測試指定或自然輸入生成。

若還原目標包含路徑生成，另從原生結果入口執行最小 typed fixture。保留來源結果、逐段展開、到站分組與最終佇列四層證據。回放輸入只取自然樣本的一部分時，明列其餘合成欄位，避免把保留自然起訖等同原局完整重播。

## 結案

分別回報自然路徑、lab 回放、靜態工具接入與未覆蓋分支。缺必要窗口記 partial／blocked。工具安裝、方法命中、靜態畫面成功均不代替動態目標驗收。

原始 trace、反編譯、物件位址與截圖留業務專案。可重用方法以候選回饋承接，獨立目標重用前不升級信心。
