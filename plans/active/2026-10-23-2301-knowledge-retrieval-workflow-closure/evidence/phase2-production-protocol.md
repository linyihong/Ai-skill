## Production interface

`runtime lookup index` builds a derived cache only. `lookup prepare` uses the production index and source-level freshness/dedup, explicitly bounded Unicode-term OR candidate generation (64 terms/sources). Exact-phrase `runtime query` remains unchanged. Promote the previously measured ATX-heading extraction fix without changing lifecycle inference. Seven selected intelligence bodies remain covered. These are candidate-generation mechanisms, not final relevance judgments.

Prepare writes a new bundle and neutral request with the byte-identical accepted selector prompt. IDs depend on query/source only; cards are opaque ID sorted with title/full indexed summary, no task_context, case ID, mapping/rank/gold/confuser/manual decisions. Missing summaries get an explicit unavailable placeholder in request only. Bundle binds actual executable, index, source checksums and request. No labels enter production calls.

Existing fresh agent runner reads only its assigned request and atomically publishes raw JSON. The production watcher validates that exact request/raw; complete requires its successful receipt and externally recorded bundle SHA. Complete checks executable/index/request identity, freshness and actual selected source checksums, then uses unchanged direct-only admission and whole-object ≤2000 runes P0 packing (full summary, need_to_read, unknown/unassessed/deferred/trace). Failed watch/parser/stale/checksum/budget state has no success payload or old-pool fallback. Actual applicability/adoption remain Phase 3.
