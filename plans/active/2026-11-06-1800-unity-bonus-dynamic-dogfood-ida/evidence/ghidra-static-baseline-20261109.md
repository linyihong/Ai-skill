# Ghidra 靜態基線

2026-11-09，Ghidra 12.2 與 Temurin 25.0.5 已在 Apple Silicon 啟用。使用官方發行包的 buildNatives 編譯本機反編譯器，成功匯入 ARM64 ELF 並完成四個函式的批次匯出。固定輸入、工具與範圍的兩次唯讀匯出逐位元一致。

以 metadata 與 LLVM 核對完成派發的欄位讀取、間接跳轉及位置收尾的狀態清除。反編譯結果仍有跨函式控制流警告，未將該段推論直接當成事件順序。具體 RVA、輸出指紋、重跑方法與兩假說預測留在 `<PROJECT_ROOT>/docs/slots/el-dorado-dices/lab/bonus-ghidra-static-baseline-20261109.md`。

靜態環境與樣本重跑通過。Runtime 位址、實際自然事件次序與動態回放尚待驗證，計畫維持 draft。

## 可獨立閱讀的分析過程

1. 用同一次 APK 抽取的 ELF 和 metadata 建索引，重新計算兩個指紋，再與手機安裝的 APK 比對。方法索引給的是 module-relative RVA，分析工具使用「image base + RVA」，不把 Ghidra 位址直接用於 Runtime。
2. 將分析範圍限在四個目標方法的入口至下一個 metadata 入口。兩次以相同輸入、工具、腳本及範圍做唯讀匯出，用位元比較判斷重現性。
3. 對照實際指令。完成派發先讀接收者的回呼容器，再跳向委派目標。位置收尾先清除 moving，再尾跳位置設定。反編譯器警告顯示可能越過方法邊界，因此用指令驗證這兩個判斷。
4. 寫下可反駁的預測後才掛探針。如果中途移動和到站共用位置收尾，兩者都應見 moving 清零；到站另有完成派發。若中途段也出現同一派發，或到站沒有派發，須用同物件與事件窗口重新裁決。

## 證據如何呈現

| 來源 | 保留的結果 | 支持的主張 |
| --- | --- | --- |
| 匯入診斷 | AArch64 little-endian、可執行段內四個入口 | 樣本與目標架構一致 |
| 兩次批次輸出 | 位元相同 | 此樣本的靜態流程可重跑 |
| 指令抽查 | 間接派發、清旗標、尾跳 | 提出事件和狀態預測 |
| 自然 Runtime | 同一棋子的中途／到站事件對照 | 後續驗證分支與順序 |

完整位址、檔案雜湊與指令輸出可在業務專案追溯。本頁保留足以解釋結論的推導。
