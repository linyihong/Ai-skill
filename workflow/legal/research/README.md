# Applicable Law Research（適用法研究與法律知識查證）

本 slice 回答：**這個交易受哪些法律約束、這些法律現在的版本是什麼、最近有沒有改**。

> **本 domain 最高風險的輸出是憑訓練記憶斷言法條。**模型知識有 cutoff，法規與官方範本
> 都會改版。本 slice 的存在就是把「未查證的法律主張」擋在產出之外。

## 五步流程

```text
1. Jurisdiction        → 鎖定法域（含多法域交錯時的優先關係）
      ↓
2. Applicable Laws     → 列出適用的法規類別與具體法規
      ↓
3. Recent Updates      → 查最新修正日／版本，以及是否影響本案結論
      ↓
4. Government Sources  → 回溯到 A 層官方來源，記錄版本與查核日
      ↓
5. Risk Summary        → 哪些結論穩固、哪些受變數影響、哪些仍 unverified
```

## Step 1 — Jurisdiction

從 [`../intake.md`](../intake.md) §S0-2 取得。多法域時要決定：

| 情況 | 處理 |
| --- | --- |
| 契約選了 A 國法 | 以 A 國法為主，但仍要檢查 B 國強制法是否插入 |
| 履約地與登記地不同 | 兩地都查；履約地的強制法通常無法規避 |
| 涉個資／勞動／消保／競爭／外匯 | 該領域**分別**查各相關法域的強制規定 |
| 法域未確認 | **停止**，回 intake（`gate.legal.intake_complete`） |

## Step 2 — Applicable Laws（先分類，再找具體法規）

先問「這個交易碰到哪幾類法」，再去找該類的具體法規。分類法比背法規名稱穩定：

| 類別 | 何時適用 |
| --- | --- |
| 契約 / 債法通則 | 一律 |
| 公司法 / 商業登記 | 締約能力、代表權、關係人交易 |
| 消費者保護 | 對方為消費者、或屬定型化契約 |
| 競爭 / 反托拉斯 | 獨家、地域限制、轉售價格、搭售 |
| 智慧財產 | IP 歸屬與授權、營業秘密 |
| 個資 / 資料保護 | 處理個資、跨境傳輸 |
| 勞動 | 涉僱傭關係（→ 多半直接 Red tier） |
| 政府採購 | 一方為機關或屬採購案 |
| 外匯 / 跨境支付 | 跨境金流 |
| 稅務 | 扣繳、租稅協定（→ 稅務規劃屬 Red tier） |
| 出口管制 / 制裁 | 技術、軟體或貨品跨境 |
| 電子簽章 / 文件形式 | 電子簽署效力、是否要求書面 |
| 產業特別法 | 金融、醫療、電信、教育等受監理產業 |

## Step 3 — Recent Updates

| 檢查 | 動作 |
| --- | --- |
| 法規最新修正公布日 | 記錄；若晚於我方既有理解，逐條比對變動 |
| 官方範本版本 | 記錄版本號；用「修正明細對照」看差異，比重讀全文快 |
| 有無過渡條款 | 新法是否適用於本案（簽約時點 / 履約時點） |
| 有無新函釋或 Q&A | 官方立場是否改變 |
| 我方引用的舊版是否仍有效 | 若對方援引舊版範本，確認是否為機關指定 |

**Staleness rule**：使用官方範本或引用法規前**必須當次核對**是否有更新版本。
「上次查過」不算，因為官方頁面同時列出多個版本，用錯版本會直接改變結論。

## Step 4 — Government Sources

| 法域 | 應查的來源類型 |
| --- | --- |
| TW | 官方法規資料庫（法規全文與最新修正日）；主管機關官網（函釋、Q&A、定型化契約應記載事項）；政府電子採購網（採購範本與相關規定）；司法院（裁判） |
| JP | 政府法令資料庫（e-Gov 類）；主管省廳官網（ガイドライン／通達） |
| US | 聯邦與**各州**法規彙編；主管機關（FTC／SEC／BIS 等）；法院公開系統 |
| EU | EU 官方法規資料庫（Regulation／Directive 原文）；**成員國**國內轉換立法；主管機關指引（如資料保護機關） |
| CN / SG / HK / 其他 | 該法域官方法規資料庫 + 主管機關官網 |

> 本表刻意**只寫來源類型不寫 URL 清單**：URL 與入口會變動，寫死會 stale。
> 台灣路徑的具體入口與已核實資訊見 [`../reference-sources.md`](../reference-sources.md)。
> 非台灣法域由 agent 於本 stage 現場查證官方來源，並在產出中記錄實際使用的來源。

**四類來源缺一不可**（範本 / 法條 / 官方 Q&A / 函釋）——見
[`../reference-sources.md`](../reference-sources.md) §四類來源。

## Step 5 — Risk Summary

不是重述法條，而是回答「哪些結論可以依賴」：

```markdown
## Legal Research Risk Summary
- 穩固結論（A 層來源 + 已核版本）: <...>
- 受變數影響的結論: <變數是什麼、往哪個方向會改變答案>
- unverified 主張: <缺什麼來源、影響哪個 Decision Register 決策點>
- 建議由律師覆核的具體問題: <具體問題，非籠統「建議諮詢」>
```

## 產出：Applicable Law Table（強制欄位）

```markdown
## Applicable Law Table
| # | 法域 | 法規 / 範本名稱 | 版本 / 最新修正日 | 條號或編號 | 來源層級 | 查核日 | Confidence |
| - | --- | --- | --- | --- | --- | --- | --- |
```

任一列缺「版本／最新修正日」或「查核日」→ 該列 `Confidence = unverified`，
且引用它的結論不得以確定語氣呈現（`gate.legal.law_citation_versioned`）。

## 常見失效模式

| 失效 | 防呆 |
| --- | --- |
| 憑記憶給條號或數字上限 | 無 A 層來源即標 unverified，不給數字 |
| 只查法條不查函釋與 Q&A | 四類來源檢查 |
| 引用「官方範本」不寫版本 | `gate.legal.source_version_pinned` |
| 用律師事務所文章當結論依據 | C 層僅作線索，需回溯 A 層 |
| 跨法域時只查一方 | Step 1 多法域處理表 |
| 忽略強制法插入 | Step 2 分類法逐類檢查 |

## 驗證

- Applicable Law Table 每列是否有版本／最新修正日 + 查核日？
- 四類來源是否都查過或標出未查證類別？
- 官方範本是否鎖定版本號、是否看過修正明細對照？
- Risk Summary 是否區分穩固結論與 unverified？
- unverified 項是否已回饋到 [`../strategy/README.md`](../strategy/README.md) 的
  Decision Register（讓 Pass 2 無法誤標 confirmed）？
