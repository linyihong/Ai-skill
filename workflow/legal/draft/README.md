# Contract Drafting（我方出稿）

適用 task type `draft`。前提：`gate.legal.intake_complete` 已通過，且
[`../strategy/README.md`](../strategy/README.md) 的 Decision Register 已由使用者確認。

> **不得跳過策略直接出稿。**Decision Register 未確認時，只能產出標記
> `<ASSUMPTION: ...>` 的骨架。

## 六步

```text
1. Skeleton        → 依交易類型選骨架，鎖定條款清單
2. Base Text       → 選底稿來源（官方範本 / 我方標準版 / 從零撰寫）
3. Decision Fill   → 把 Decision Register 的已確認決策落成條款文字
4. Protection Pass → 我方保護條款完整性檢查
5. Consistency     → 定義、交叉引用、附件、雙語一致性
6. Handover        → 產出 + 假設清單 + 需使用者決策項 + 簽署前檢核
```

## Step 1 — Skeleton

標準骨架（依交易類型增減）：

當事人與定義 → 標的與範圍（含附件）→ 對價與付款 → 交付與驗收 → 期間與續約 →
雙方義務 → 陳述與保證 → 保密 → 智慧財產 → 資料與個資 → 責任與上限 →
違約與救濟 → 不可抗力 → 終止與存續 → 轉讓與控制權變更 → 通知 →
準據法與爭議解決 → 一般條款（完整合約、可分性、修改形式、副本）→ 附件

**先鎖清單再寫文字**。清單缺項是最貴的錯誤（見
[`../review/README.md`](../review/README.md) Stage 4）。

## Step 2 — Base Text

| 底稿來源 | 何時用 | 注意 |
| --- | --- | --- |
| 官方範本 | 政府採購、有官方定型化範本的領域 | **必須鎖定版本號**；記錄機關有無增修（`gate.legal.source_version_pinned`） |
| 我方標準版 | 重複性交易 | 確認標準版本身是否已依最新法規更新 |
| 對方版本改寫 | 對方堅持用其範本 | 改為 `review` + redline，不要當成 draft |
| 從零撰寫 | 無成熟範本的新型交易 | 條款清單完整性風險最高，Step 1 要更嚴 |

## Step 3 — Decision Fill

Decision Register 的每個 `confirmed` 決策必須落成具體條款，且**可追溯**：

```markdown
| Decision # | 決策 | 落在哪一條 | 條款要點 |
| --- | --- | --- | --- |
```

未確認（`provisional`）的決策 → 該條款標 `<ASSUMPTION: ...>`，不得寫成確定文字。

## Step 4 — Protection Pass

依我方角色檢查保護完整性（不是要求全部有利，而是不要漏）：

| 面向 | 檢查 |
| --- | --- |
| 責任 | 上限金額或計算方式；間接／衍生損失排除；上限的例外（故意、保密違反、IP 侵權） |
| 付款 | 節點與尾款比例是否覆蓋收尾成本；逾期利息；抵銷權 |
| 驗收 | 標準／測試／期限／修正機會／sign-off 五項齊備 |
| IP | 逐類歸屬（交付碼／既有元件／第三方 OSS／資料／模型／prompt／輸出） |
| 保密 | 分層期間；例外；返還銷毀；救濟 |
| 資料 | 個資角色分工；跨境傳輸依據；終止後匯出 |
| 終止 | 我方退出路徑；對方立即解除事由是否過寬；存續條款 |
| 不可抗力 | 履約地實際風險具名；不免除已到期價金 |
| 變更 | 需求變更程序與費用調整；避免無償變更義務 |
| 陳述保證 | 對方締約能力、簽署權限、無侵權、無制裁名單 |
| 擔保 | 依背調 risk flag 決定是否要母公司保證／保證金 |

## Step 5 — Consistency

| 檢查 | 常見錯誤 |
| --- | --- |
| 定義 | 定義了沒用；用了沒定義；同一概念兩個定義 |
| 交叉引用 | 「依第 X 條」指向錯誤或不存在條號 |
| 附件 | 附件被引用但未附；附件未被正文納入 |
| 數字與期限 | 前後不一致；中文數字與阿拉伯數字不符 |
| 雙語 | 兩版實質不一致；未寫明優先版本 |
| 條號 | 重複、跳號、層級混亂 |

## Step 6 — Handover

```markdown
## Draft Handover
- 底稿來源: <官方範本 vX.Y / 我方標準版 / 從零>（含版本與查核日）
- Decision → 條款對照表
- 假設清單: <每個 <ASSUMPTION> 對應條款與待確認事項>
- 需使用者決策: <具體決策點>
- 簽署前檢核: 簽署人權限文件、附件齊備、印鑑或電子簽章方式、份數、生效條件
- 需律師覆核的具體條款: <清單，非籠統建議>
- Disclaimer
```

## 驗證

- Step 1 條款清單是否完整（對照 [`../review/README.md`](../review/README.md) Stage 4 缺漏表）？
- 底稿若為官方範本，版本號是否鎖定？
- 每個 Decision Register 的 confirmed 項是否都落成條款且可追溯？
- `provisional` 項是否都標 `<ASSUMPTION>`？
- Protection Pass 十一個面向是否逐項檢查？
- 定義／交叉引用／附件／雙語一致性是否檢查過？
