# Legal Task Intake（分層問卷）

本檔是 `workflow/legal/` Stage 1 的 canonical source：**要問什麼、依什麼順序問、什麼時候
可以停止問**。問卷分層是為了不要一次丟 30 個問題給使用者。

> **Blocking rule**：`S0` 未答完（或未標記假設）不得產出條款全文、不得給法律結論。
> 只能輸出 `Legal Task Frame`（未知欄位標 `UNKNOWN`）+ blocking 問題清單。

## 問法（一次問幾題）

一輪問 3–6 題，優先問**會改變下游流程**的題目。已能從使用者訊息推得的不要重問，
但要在 Frame 中標明「推定值」讓使用者可否認。

## S0 — 必問（任何法律任務）

| # | 問題 | 為何 blocking |
| --- | --- | --- |
| S0-1 | **你要做什麼？** draft / review / explain / compare / research / due-diligence / negotiation-support / lifecycle | 決定第一級分派；推定錯會跑錯整條 flow |
| S0-2 | **適用法域（Jurisdiction）？** TW / JP / US（哪一州） / EU（哪一國） / CN / SG / Other | **P0**。同一條款在不同法域效果不同 |
| S0-3 | **我方角色？** 出稿方 / 審閱方 / 談判代表 / 內部評估 | 決定紅線設計方向與產出形狀 |
| S0-4 | **對手方是誰？** 法人全稱 + 登記地 + 統編／註冊號（若有） | 決定要不要跑背調、跨境與否 |
| S0-5 | **交易實質是什麼？** 一句話描述誰給誰什麼、換到什麼 | 條款只是包裝，實質錯了條款全錯 |
| S0-6 | **金額量級與付款方式？** 一次付／分期／里程碑／訂閱 | 決定 risk tier 與擔保條款強度 |
| S0-7 | **期間與終止預期？** 固定期／不定期／自動續約；預期怎麼結束 | 終止與存續條款的前提 |
| S0-8 | **硬期限？** 什麼時候要簽、有無投標／董事會／會計期間限制 | 決定能做多深，也決定要不要先給骨架 |
| S0-9 | **合約已簽署了嗎？** 未簽／已簽／已簽且期間屆滿 | 決定 review 的產出形狀——已簽署時修正條文無收件人（見 [`review/README.md`](review/README.md) §Stage 5B） |

**S0-9 答「已簽署」時追問**（事實狀態是風險評估的輸入，不是背景）：

| 追問 | 為什麼 |
| --- | --- |
| 履約進度到哪？已交付什麼？ | 決定可否主張割合報酬 |
| 款項收到第幾期？未收多少？ | 未收款是時效與請求策略的起點 |
| 有無停滯？**原因可歸責於哪一方？** | 同一條懲罰性條款，歸責不同威脅程度天差地遠 |
| 對方有無主張過我方違約、或要求返還？ | 若有 → 已進入爭議，依 [`risk-classification.md`](risk-classification.md) **升 Red** |
| 有無收到催告、正式請求或訴訟文書？ | 同上，且有回應期限 |

`S0-2` 未知時，**不得**進行任何法域特定的條款分析；可先做法域中立的結構檢查。

## S1 — 依合約／文件類型分支

只在 task type 涉及具體文件時問。

### 保密（NDA / 保密協議）
保密資訊定義範圍；單向或雙向；保密期間（含期滿後）；例外（已公開／獨立開發／法令要求揭露）；
殘留記憶條款；返還或銷毀義務；違約救濟（違約金或實際損害）。

### 服務 / 委外開發
SOW 與交付項（含附件是否被正文納入）；驗收標準／測試／期限／修正／sign-off；
是否採默示驗收（逾期未回覆＝通過或不通過）；階段成果確認天數；
變更控制五步（申請→評估→確認→重訂時程→實施與紀錄）與「範圍內免加價」的判定邊界；
付款節點與「交付代碼」完成定義；保固範圍（錯誤修正 vs 新功能）與期間；
IP 逐類歸屬（客製碼／供應方套件／「供應方提出之功能」／第三方 OSS）；
開發費是否捆綁主機或維護（若是：SLA、續約、遷移）；SLA 未達救濟；人員替換與競業限制。

### 財物採購 / 買賣
規格與檢驗方式；交貨條件（跨境時的 Incoterms 版本）；風險與所有權移轉時點；
瑕疵擔保期；退換貨；包裝運送責任；價格調整機制。

### 政府採購（走 [`reference-sources.md`](reference-sources.md) 官方路徑）
招標文件編號與案號；採購類別（工程／統包工程／財物／勞務／資訊服務／資訊雲端服務）；
決標方式；履約期限與展延條件；押標金／履約保證金；逾期違約金計算方式與上限；
驗收程序；轉包與分包限制；契約變更與物價調整；爭議處理（申訴／調解）。
**必問**：機關使用的是官方範本第幾版、有無機關自訂增修條款。

### 代理 / 經銷
獨家性（獨家／非獨家／地區獨家）；地域與通路範圍；最低採購量或業績目標；
價格與轉售價格限制（注意競爭法）；商標與品牌使用；終止事由與存貨處理；
終止後客戶名單與補償。

### 授權（Software License / IP License）
授權範圍（用途／人數／地域／期間）；可否再授權與轉讓；audit 條款的範圍與頻率；
indemnity（侵權擔保）範圍與上限；開源元件合規；資料使用權；服務終止後的資料匯出。

### MOU / LOI
**是否要有法律拘束力**（哪些條款有、哪些沒有必須逐條寫明）；排他期間；
保密；費用分擔；後續正式合約的談判義務強度；失效條件。

### 勞動相關
→ 直接進 [`risk-classification.md`](risk-classification.md)，判定 **Red**。本 workflow 不產出
實質建議。

## S2 — 依我方角色分支

### 出稿方（draft）
我方 must-have 清單（責任上限、間接損失排除、IP 歸屬、保密、終止權、不可抗力、
準據法與管轄）；可讓步項與底線；是否需要對方提供擔保（母公司保證／履約保證金／預付款）；
簽署人與內部核決層級。

### 審閱方（review）
對方稿的來源（官方範本／對方自製／上一版修改）；我方絕對不能接受的條款（紅線）；
商業上已談定不可再動的部分；審閱交付形式（memo／redline／逐條表）；時間壓力。

### 談判代表（negotiation-support）
已達成與未達成的爭點；對方已表明的立場與理由；我方 BATNA；
可交換的籌碼（價格／期間／範圍／付款條件）；決策授權範圍。

## S3 — 跨境加問（jurisdiction ≥2 法域或非 TW）

→ 正文在 [`jurisdiction.md`](jurisdiction.md)。至少問：契約語言與版本優先；準據法；
爭議解決（法院或仲裁、機構、地點、語言）；對手方資產所在地與判決／仲裁裁決可執行性；
制裁與出口管制暴露；個資跨境傳輸；稅務（扣繳、租稅協定）；幣別與匯率風險。

## 產出：Legal Task Frame

```markdown
## Legal Task Frame
- Task type: <draft|review|explain|compare|research|due-diligence|negotiation-support|lifecycle>
- Jurisdiction: <TW|JP|US-XX|EU-XX|... | UNKNOWN>
- 我方角色: <出稿方|審閱方|談判代表|內部評估 | UNKNOWN>
- 對手方: <法人全稱 + 登記地 + 登記號 | UNKNOWN>
- 交易實質: <一句話>
- 金額量級 / 付款: <... | UNKNOWN>
- 期間 / 終止預期: <... | UNKNOWN>
- 硬期限: <... | UNKNOWN>
- Risk tier: <Green|Yellow|Red>（依 risk-classification.md）
- 推定值（使用者可否認）: <欄位=推定值，理由>
```

## Missing Information Gate

| 狀況 | 允許的產出 | 禁止的產出 |
| --- | --- | --- |
| S0 有 blocking 欄位 UNKNOWN | Frame + blocking 問題清單 + 法域中立的結構檢查清單 | 條款全文、法律結論、風險評分 |
| 使用者說「先給我看骨架」 | 標記 `<ASSUMPTION: ...>` 的條款骨架，每個假設逐一點名 | 未標記假設的骨架；把假設藏在條款文字裡 |
| 使用者拒答某題 | 記為 `DECLINED` 並說明它會讓哪個分析降級 | 靜默填入預設值 |

## 驗證

- Frame 是否所有欄位都有值或明確 `UNKNOWN` / `DECLINED`？
- Jurisdiction 是否已確認或已列為 blocking 問題？
- 推定值是否已列出讓使用者可否認？
- 若已產出骨架，每個假設是否都有 `<ASSUMPTION>` 標記？
