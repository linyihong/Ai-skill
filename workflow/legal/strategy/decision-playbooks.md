# Strategy Decision Playbooks

九個反覆出現的決策點：**要推理哪些因素、常見結論、以及什麼情況下結論會反轉**。

> **Playbook 是推理起點，不是答案。**每個「常見結論」都必須經本案的 Interest Analysis
> 與 Research 調整；直接套用而不綁本案因素，是本 slice 明文列出的失效模式。
> 輸出一律走 [`README.md`](README.md) §Decision Reasoning 四欄格式。

## 1. 準據法（Governing Law）

**推理因素**：哪一國法對本交易類型規則成熟；哪一方熟悉（律師成本）；
判決／裁決在對手方資產所在地是否容易執行；是否有強制法無法用選法規避
（勞動、消保、競爭、個資、外匯）。

| 情境 | 常見結論 | 反轉條件 |
| --- | --- | --- |
| 雙方同法域 | 該法域法 | 交易標的在第三地且該地強制法適用 |
| 我方主導、對方議價力弱 | 我方法域法，用其他條件交換 | 對方內部政策硬性禁止外國法 |
| 對等跨境 | 中立第三法域法（規則成熟、雙方皆可取得專業服務） | 該法對本交易類型無成熟規則 → 回到一方本國法 |
| 涉強制法領域 | **選法無效**，直接按強制法規劃 | 無 |

## 2. 管轄 / 爭議解決（Court vs Arbitration）

**推理因素**：雙方所在地；訴訟／仲裁成本（律師、翻譯、差旅）；語言；
判決 vs 仲裁裁決在對手方資產地的可執行性；保密需求；爭議金額分布；速度。

| 情境 | 常見結論 | 反轉條件 |
| --- | --- | --- |
| 雙方同法域、金額不大 | 我方所在地法院，專屬管轄 | 對方為公部門或有特殊管轄規定 |
| 跨境、對等 | 中立地仲裁（機構 + seat + 人數 + 語言四項寫齊） | 金額小到仲裁不經濟 → 加金額門檻，門檻下先協商／調解 |
| 跨境、我方議價力強 | 我方法院或我方偏好 seat | 對手方資產地不承認該判決 → 改仲裁 |
| 對方堅持其本國 | 退讓順序：中立地仲裁 > 對方國仲裁機構 > 對方國法院 | 對方國法院程序風險過高 → 不簽 |
| 政府採購 | 依法定異議／申訴／調解程序 | 契約不得任意排除 |

**成本不對稱原則**：選任一方本國法院時，另一方承擔翻譯、當地律師、差旅與執行成本。
這是對方拒絕的主要理由，也是我方要求交換條件的槓桿。

## 3. 付款條件（Payment Terms）

**推理因素**：對手方信用（首次合作？背調結果？）；交付性質（一次性 vs 持續）；
我方現金流；跨境收款風險；是否有驗收爭議空間。

| 情境 | 常見結論 | 反轉條件 |
| --- | --- | --- |
| 首次合作、信用未知（我方為供應方） | 分期並前重後輕（例：簽約 30% / 里程碑 40% / 驗收 30%），保留尾款比例足以覆蓋收尾成本 | 對方為大型可信主體且政策不允許預付 → 改縮短帳期 + 加逾期利息 |
| 政府採購 | **依驗收付款**，不建議設計預付款期待 | 招標文件另有預付款規定（依文件辦理） |
| 跨境、對手方信用不明 | 信用狀（L/C）／Escrow／銀行保函／預付比例提高 | 金額小到擔保工具成本不合理 → 提高預付比例 |
| 我方為採購方 | 尾款綁驗收合格 + 保固保留款 | 對方為市場稀缺供應者，議價力低 |
| 長期訂閱 | 預繳週期 + 調價機制 + 未使用期間處理 | — |

**尾款原則**：尾款要能覆蓋「對方不履行收尾義務」的成本（文件移交、教育訓練、資料匯出）。

## 4. 違約金 / 損害賠償（Liquidated Damages）

**推理因素**：標的類型（工程／財物／服務／軟體／授權）；損害是否易證明；
上限設計；與終止權的關係；當地法對過高違約金的酌減。

| 標的 | 常見設計 | 注意 |
| --- | --- | --- |
| 工程 / 財物交付 | 逾期日數 × 契約金額比例，設總額上限 | 上限過低等於允許延遲 |
| 服務 / 維運 | SLA 未達 → 服務費折抵（service credit） | 折抵是否為**唯一**救濟要談清楚 |
| 軟體開發 | 里程碑逾期扣款 + 重大逾期可終止 | 需求變更造成的延遲要排除 |
| 授權 / IP | 侵權 indemnity 為主，違約金為輔 | indemnity 上限與保險連動 |
| 保密違反 | 難證明實際損害 → 約定金額 + 併得請求實際損害與禁制救濟 | 過高可能被酌減 |

**設計原則**：違約金不是罰款，是**免除舉證的預估損害**。設在「可信的損害預估」附近才易維持。

## 5. 智慧財產（IP）

**推理因素**：誰出資、誰出既有資產、後續誰要商業化；是否含第三方元件與 OSS；
是否需要對方保留改良權。

軟體／AI 專案要**逐類**決定，不能一句「IP 歸我方」：

| 資產類別 | 常見安排 | 注意 |
| --- | --- | --- |
| 交付的 Code（客製部分） | 出資方取得所有權或永久授權 | 開發方常要求保留可重用元件 |
| 開發方既有元件 / Framework | 開發方保留所有權，授予客戶必要範圍的永久授權 | 未寫清楚會讓交付物無法使用 |
| 第三方元件 / OSS | 列清單 + 授權條款 + 合規責任歸屬 | copyleft 元件會影響交付物可否閉源 |
| Model（權重） | 依出資與資料來源分配；可約定專屬使用期 | 基礎模型的授權條款可能限制轉授權 |
| Dataset | 區分「客戶提供」與「開發方蒐集」；客戶資料通常歸客戶 | 個資與跨境傳輸另受法規約束 |
| Training Data / 衍生資料 | 是否允許用於改良通用模型、是否需去識別化 | 這是 AI 專案最常爆的爭點 |
| Prompt / 系統提示 | 常被遺漏；明確歸屬與保密等級 | — |
| Fine-tuned 產出 / 輸出內容 | 輸出的權利歸屬與可否用於訓練 | — |

**三問法**：哪些必須**保留**（我方核心資產）、哪些可**授權**（範圍／期間／地域）、
哪些**不可移轉**（第三方授權限制或法規限制）。

## 6. 保密（Confidentiality）

**推理因素**：合作期間長度；資訊的商業壽命；是否含營業秘密；期滿後的殘留義務。

| 情境 | 常見結論 | 反轉條件 |
| --- | --- | --- |
| 一般商務往來 | 合作期間 + 期滿後固定年數（與資訊商業壽命相稱） | — |
| 含營業秘密 / 配方 / 演算法 | 該類資訊**不設期限**，其餘資訊設期限（分層） | 一律永久會讓對方拒簽 |
| 技術快速迭代領域 | 較短期間即足夠 | — |
| 個資 | 保密期間之外另受個資法規約束，不可用契約縮短 | — |

**避免**：整份「永久保密」。合理性受質疑，且實務上難執行。改用**分層期間**。

## 7. 驗收（Acceptance）

**推理因素**：交付物可否客觀量測；爭議空間；付款綁定。

只寫「完成後付款」是最常見的高風險設計——「完成」由誰認定會直接變成付款爭議。

| 缺失 | 補上 |
| --- | --- |
| 無驗收標準 | 明確、可量測的 Acceptance Criteria（對應 SOW 逐項） |
| 無驗收測試 | Acceptance Test 程序、環境、資料、由誰執行 |
| 無期限 | 驗收期（逾期未表示視為通過／不通過，二者擇一並寫明） |
| 無修正機會 | Correction Period + Retry 次數上限 |
| 無最終確認 | Sign-off 形式（書面／系統紀錄）與代表人 |
| 部分驗收 | 可否分批驗收與分批付款 |

## 8. 不可抗力（Force Majeure）

**推理因素**：履約地的實際風險；供應鏈是否跨境；是否有替代履行方式。

| 履約地 / 情境 | 應具名列入 |
| --- | --- |
| 日本 | 地震、颱風、海嘯 |
| 台灣 | 颱風、地震、限水限電 |
| 跨境供應鏈 | 港口封鎖、出口管制變更、戰爭與制裁 |
| 通用 | 疫情與公共衛生措施、政府命令 |

**結構要寫齊**：構成事由（具名 + 概括）、通知義務與期限、履約中止效果、
持續超過 X 期間的終止權、費用負擔、是否排除付款義務（通常**不**免除已到期價金）。

## 9. 終止（Termination）

**推理因素**：誰的退出成本高；轉換供應商的難度；已投入的專屬投資。

| 決策 | 推理 |
| --- | --- |
| 誰比較容易退出 | 退出成本低的一方應被限制（較長通知期或補償） |
| 任意終止（for convenience） | 我方要不要有？給對方會讓長期投資無保障 → 若給，加通知期 + 已投入成本補償 |
| 通知期 | 與轉換所需時間相稱（找替代供應商、移轉資料） |
| 立即解除事由（重大違約） | 逐項列舉：未付款達 X 日、保密重大違反、破產／重整、控制權變更、違法 |
| 補正期 | 可補正的違約給補正期；不可補正的直接解除 |
| 終止後義務（存續條款） | 保密、IP、資料返還／匯出、已交付部分的付款、過渡協助期 |

**存續條款最常被漏**。終止不等於所有義務消滅，要明列哪些條款存續多久。

## 驗證

- 每個用到的 playbook，Reason 欄是否綁**本案**因素（而非抄「常見結論」）？
- 是否檢查過反轉條件？
- IP 是否逐類決定（而非一句歸屬）？
- 驗收是否具備標準／測試／期限／修正／sign-off 五項？
- 終止是否寫了存續條款？
