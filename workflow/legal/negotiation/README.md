# Negotiation Support（談判支援）

適用 task type `negotiation-support`，以及 `draft` / `review` 進入多輪來回之後。
本 slice 不重做風險分析（那是 [`../review/README.md`](../review/README.md) 的事），
而是把已知風險與策略轉成**可執行的談判動作**。

## 四個核心產出

```text
1. Issue Ledger        → 爭點收斂表（每個爭點的雙方立場與現況）
2. Concession Matrix   → 讓步矩陣（什麼可換什麼、順序）
3. Version Tracking    → 多輪 redline 版本追蹤
4. Round Brief         → 每一輪的談判準備摘要
```

## 1. Issue Ledger（爭點收斂）

```markdown
| # | 爭點 | 條號 | 我方立場 | 對方立場 | 對方理由 | 級別 | 狀態 |
| - | --- | --- | --- | --- | --- | --- | --- |
```

- **級別**沿用 review 的 Critical / Major / Minor。
- **狀態**：`open` / `converging` / `agreed` / `deadlocked` / `parked`。
- **對方理由**是最有價值也最常漏的一欄。不知道對方為什麼堅持，就無法設計交換。

**收斂紀律**：每輪結束後把 `agreed` 移出主表（另存已定案清單），主表只留未決。
爭點數字持續不降＝談判在原地繞。

## 2. Concession Matrix（讓步矩陣）

讓步不是逐項退讓，而是**用低價值項換高價值項**。

```markdown
| 項目 | 對我方價值 | 對對方價值（推測 + 依據） | 可讓程度 | 換取什麼 |
| --- | --- | --- | --- | --- |
```

| 可讓程度 | 意義 |
| --- | --- |
| `red-line` | 不可讓。讓了就不簽 |
| `costly` | 可讓但要對價 |
| `cheap` | 對我方影響小，可作為交換籌碼 |
| `already-conceded` | 已讓，不可重複當籌碼 |

**設計原則**：
- 對我方 `cheap` × 對對方高價值 = 最佳籌碼，優先用。
- `red-line` 要在早期就明說，避免對方以為可談而累積期待。
- 每次讓步都要**明確綁定**換取項，不做單方讓步（單方讓步會被視為還有空間）。

籌碼來源：`Trade-offs` 欄（[`../strategy/README.md`](../strategy/README.md)）與
交易槓桿（價格、期間、範圍、付款條件、獨家性、數量承諾）。

## 3. Version Tracking

```markdown
| 版本 | 日期 | 提出方 | 主要變動 | 我方回應狀態 |
| --- | --- | --- | --- | --- |
```

必守規則：

- **每輪都要 diff**，不憑印象。對方可能在無關條款夾帶變動。
- 特別檢查「看似小但實質重大」的改動：「應」↔「得」、上限數字、天數、
  加入「唯一救濟」、刪除例外、定義範圍擴縮。
- 已 `agreed` 的條款被改動 → 立即標出，這是談判信號不是筆誤。
- 保留每一版，不要覆蓋。

## 4. Round Brief（每輪準備）

```markdown
## Round <N> Brief
- 本輪目標: <要收掉哪 2–3 個爭點>
- 對方預期立場: <依上一輪推測>
- 可用籌碼: <本輪打算動用哪些 cheap 項，換什麼>
- 絕不鬆動: <本輪的 red-line>
- 若對方提出 X: <預先準備的回應與退讓路徑>
- 最差可接受結果（本輪）: <...>
- BATNA 提醒: <不簽的替代方案是什麼，還剩多少時間>
```

**BATNA 紀律**：BATNA 弱時不要虛張，改為爭取時間或縮小範圍先簽；
BATNA 強時可明確設期限。BATNA 未評估就進談判是常見失誤。

## Deadlock 處理

| 症狀 | 處置 |
| --- | --- |
| 同一爭點三輪無進展 | 改變維度（拆條款、加期限條件、改試行期、加金額門檻） |
| 對方拒絕理由不明 | 直接問「這條的顧慮是什麼」，多數僵局來自誤解 |
| 雙方 red-line 直接衝突 | 評估不簽的成本；不要用「先簽再說」處理 red-line |
| 對方換人／換立場 | 回到 Issue Ledger 重新確認已定案項是否仍成立 |
| 時間壓力被利用 | 把硬期限與讓步脫鉤，明說「期限不改變 red-line」 |

## 邊界

- 本 slice 提供**談判策略與文件準備**，不代表使用者對外發言或發送文件。
- 對外發送任何文件前需使用者確認（見 [`../artifact-gates.md`](../artifact-gates.md)）。
- 涉爭議已發生、訴訟或行政程序 → **Red tier**，改走
  [`../risk-classification.md`](../risk-classification.md) 升級路徑。

## 驗證

- Issue Ledger 是否有「對方理由」欄且已填？
- 未決爭點數是否逐輪下降？
- 每次讓步是否綁定換取項？
- 是否每輪都做過 diff（而非憑印象）？
- BATNA 是否已評估並寫入 Round Brief？
